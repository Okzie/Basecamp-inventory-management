System Architecture

Factory Inventory Management System

A demo full-stack application for inventory tracking, order management, demand forecasting, and spending analytics. Vue 3 single-page frontend, FastAPI backend, and JSON-backed in-memory data — no database, no auth.

Tech Stack

Three logical tiers, plus tooling for development and testing.

Frontend
Vue 3 + Vite
Composition API · SPA · port 3000
  • vue 3.4 (Composition API)
  • vue-router 4
  • axios for HTTP
  • Vite 5 dev server & build
  • Hand-rolled SVG charts (no chart lib)
Backend
FastAPI (Python)
REST API · port 8001 · auto-docs at /docs
  • FastAPI ≥ 0.110
  • Pydantic v2 for validation
  • uvicorn ASGI server
  • uv for env & deps
  • CORS wide open (demo)
Data Layer
In-Memory JSON
No database — loaded once at startup
  • server/data/*.json fixtures
  • Loaded by mock_data.py
  • Mutations don't persist
  • Restart = reset to JSON state
Testing & Tooling
pytest + Playwright MCP
~51 API tests
  • pytest 8 + FastAPI TestClient
  • httpx, pytest-asyncio, pytest-cov
  • Playwright MCP for browser checks
  • GitHub MCP for repo operations

System Architecture

Three-tier separation with a thin API boundary between Vue and FastAPI.

Request Lifecycle

A single user interaction (e.g. changing a filter on the Dashboard) traces through all tiers.

User changes a filter
FilterBar.vue updates shared refs in useFilters().
View reacts
A watch() on filter refs triggers loadData() in the active view.
api.js builds request
Constructs URLSearchParams; values equal to 'all' are dropped.
HTTP GET to FastAPI
e.g. GET /api/dashboard/summary?warehouse=East&month=Q2-2025
Server filters in-memory
apply_filters() + filter_by_month() over the loaded lists.
Pydantic validates
response_model coerces and validates the payload before send.
View stores raw data
Response assigned to a ref (e.g. allOrders).
Computed derive UI
computed() recomputes totals, groups, and chart data automatically.

Filter System

Four global filters apply consistently across the app via query params.

The four filters

  • warehouse — East / West / Central / etc.
  • category — Circuit Boards, Sensors, Actuators, Controllers, Power Supplies
  • status — Delivered / Shipped / Processing / Backordered
  • month — YYYY-MM or Q1-2025…Q4-2025

Where filters live

  • Refs defined in composables/useFilters.js (module-scoped, shared)
  • Bound by components/FilterBar.vue
  • Forwarded by every relevant api.js method
  • Stripped server-side when value is 'all'
  • Inventory ignores month — no time dimension on stock

API Endpoints

All endpoints are read-only GETs over JSON. Filters are optional query params.

Endpoint Filters Notes
GET/api/inventory warehousecategory All stock items with reorder points
GET/api/inventory/{id} — Single item lookup; 404 if missing
GET/api/orders warehousecategorystatusmonth Customer orders with line items
GET/api/orders/{id} — Single order; 404 if missing
GET/api/demand — Demand forecasts per SKU with trend
GET/api/backlog — Augments each item with has_purchase_order
GET/api/dashboard/summary warehousecategorystatusmonth Aggregated KPIs for the dashboard
GET/api/spending/summary — Top-level spend totals
GET/api/spending/monthly — Spend grouped by month
GET/api/spending/categories — Spend grouped by category
GET/api/spending/transactions — Recent transactions feed
GET/api/reports/quarterly — Computed quarterly performance from orders
GET/api/reports/monthly-trends — Month-over-month order & revenue trends

Key Conventions & Gotchas

Project-specific rules that aren't obvious from the code alone.

Reactivity rules

  • Raw API data in refs (allOrders, inventoryItems).
  • Anything derived (filters, groupings, totals) in computed.
  • Don't re-filter on the client when the server already accepts the query param.

Common pitfalls

  • Never use array index as v-for key — use sku, id, month, …
  • Validate dates with !isNaN(d.getTime()) before .getMonth().
  • Changing JSON schema requires updating the matching BaseModel.
  • No month filter on inventory endpoints.

Design system

  • Palette: slate / gray (#0f172a, #64748b, #e2e8f0).
  • Status colors: green / blue / yellow / red.
  • Charts: hand-rolled SVG. Layouts: CSS Grid.
  • No emojis in UI.

Demo constraints

  • CORS wide open — demo only.
  • No auth, no rate limit, no persistence.
  • Revenue targets baked in: $800K/month, $9.6M YTD.
  • api.js references /api/tasks & /api/purchase-orders — server routes not yet implemented.

Running Locally

One command to start both servers; or run each tier manually.

# Easy mode — boots backend (8001) + frontend (3000)
./scripts/start.sh
./scripts/stop.sh

# Manual — backend
cd server
uv venv && uv sync
uv run python main.py

# Manual — frontend
cd client
npm install
npm run dev

# Tests
cd tests
uv run pytest -v
